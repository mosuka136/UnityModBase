## Lifecycle

### `UnityModBase.UnityModBase`

The process-level entry point. Initialization and disposal are serialized by an internal lock.

```csharp
public static void Initialize(string baseDirectory);
public static void Dispose();
```

`Initialize` performs the following work:

1. Normalizes the data directory, appending a `UnityModBase` child directory unless the final segment already has that name.
2. Creates UnityModBase's own user, configuration, and logging services.
3. Scans currently loaded assemblies and starts listening for later assembly loads.
4. Registers types and methods marked with game-boot attributes.

It does not call `GameBootRegistry.Boot`. If initialization fails, the framework rolls back established state and rethrows the original exception.

`Dispose` dispatches quit handlers, stops the boot registry, disposes framework services and all user contexts, and clears frame and language events. Disposal that touches Unity objects must run on the main thread.

### `GameBootRegistry`

```csharp
public static event Action OnGameBoot;

public static void Boot();
public static void RegisterAssemblies(params Assembly[] assemblies);
public static void RegisterAssembly(Assembly assembly);
public static bool RegisterComponentOnGameBoot(Type type);
public static bool RegisterMethodOnGameBoot(MethodInfo method);
public static bool IsShouldSkipAssembly(Assembly assembly);
```

- `Boot` dispatches only once during the current initialization cycle.
- A failing startup handler is logged without stopping later handlers.
- Extensions in assemblies loaded after boot are not invoked retroactively.
- `RegisterComponentOnGameBoot` accepts types derived from `UnityEngine.Component`.
- A valid `RegisterMethodOnGameBoot` target must be a non-generic, parameterless, static `void` method. The signature is validated when the handler runs.
- Registered components are created on hidden, persistent `GameObject` instances and destroyed during framework disposal.

### `FrameUpdateManager`

```csharp
public static event Action OnFrameUpdate;
```

`FrameUpdateManager.Updater` is created at game boot and dispatches the event synchronously from every Unity `Update` on the main thread. Ordinary subscriber exceptions are logged. A `MissingMethodException` causes the invalid subscription to be removed.

### `GameQuitManager`

```csharp
public static event Action OnGameQuit;
```

The event runs once when Unity quits or the framework is explicitly disposed. The current subscription list is cleared before invocation, and one failing callback does not stop the rest.

## Users and resource scopes

### `UserManager`

```csharp
public static event Action<UserContext> OnUserRegistered;
public static event Action<string> OnUserRemoved;
public static event Action<UserContext> OnConfigChanged;

public static IEnumerable<string> UserIds { get; }
public static IEnumerable<UserContext> UserContexts { get; }

public static UserContext Register(string userId, Translator name);
public static UserContext CreateUser(string userId, Translator name);
public static UserContext GetUser(string userId);
public static bool ContainsUser(string userId);
public static string GetDefaultUserId();
public static void RemoveUser(string userId);
```

`Register` is the preferred mod entry point:

- An empty ID is generated automatically.
- A random suffix is appended if the requested ID conflicts.
- User-level configuration change forwarding is connected automatically.
- `OnUserRegistered` is dispatched after registration completes.

`CreateUser` is a lower-level entry point. It returns an existing context for a duplicate ID and does not dispatch registration events or connect global configuration change forwarding.

`UserIds` and `UserContexts` are live registry views, not snapshots. Do not continue enumerating them while the registry changes. `UserManager` is not a concurrent collection and must be accessed serially.

### `UserContext`

```csharp
public UserContext(string userId, Translator name);

public string UserId { get; }
public Translator Name { get; }
public UserService Service { get; set; }

public void AddChildContext(string key, IUserContext context);
public IUserContext GetChildContext(string key);

```

`AddChildContext` transfers lifecycle ownership of the child to the user. `RemoveChildContext` only removes the registration; it does not dispose the object, whose lifetime then becomes the caller's responsibility. Do not create parent-child reference cycles.

### `IUserContext`


A custom per-user module context can implement this interface, be attached to a `UserContext`, and be disposed with its owner.

### `UserService`

```csharp
public UserService(string userId);

public string UserId { get; }

public LogWriter LogWriter { get; }
```

Registering configuration again disposes the previous `ConfigService`; registering logging again disposes the previous `LogWriter`. Handlers registered through `UserService.OnConfigChanged` migrate to a replacement configuration service. Handlers attached directly to the old `ConfigService` do not migrate.

## Configuration

### Basic flow

```csharp
UserContext user = UserManager.Register(
    "com.example.mod",
    new Translator("示例", "Example"));

user.Service.RegisterConfig<ModConfig>(configPath);

ConfigService config = user.Service.Config;
config.CreateTable("General", new Translator("通用", "General"));

ConfigEntry<bool> enabled = config.Bind(
    "General",
    "Enabled",
    true,
    new Translator("启用", "Enabled"));

enabled.OnValueChanged += (sender, value) => ApplyEnabled(value);
```

Table and entry keys must be non-empty and contain only Unicode letters, digits, or underscores.

### `ConfigService`

```csharp
public ConfigService(string filePath);

public event Action OnConfigChanged;

public string FilePath { get; set; }
public bool SaveOnConfigSet { get; set; }
public ConfigFileSheet FileSheet { get; }
public ConfigSheet Sheet { get; }

public void CreateTable(
    string key,
    Translator name,
    Translator description = null);

public ConfigEntry<T> Bind<T>(
    string tableKey,
    string key,
    T defaultValue,
    Translator name,
    Translator description = null);

public ConfigEntry<T1, T2> Bind<T1, T2>(
    string tableKey,
    string key,
    T1 defaultValue1,
    T2 defaultValue2,
    Translator name,
    Translator description = null,
    Translator valueDescription1 = null,
    Translator valueDescription2 = null);

public bool Read();
public bool Reload();
public bool Save();
public bool Write();
public void Dispose();
```

Usage constraints:

- `filePath` must include a directory component.
- Call `CreateTable` before binding entries in that table.
- A runtime table or configuration key cannot be declared twice.
- A valid file value takes precedence over the default declared in code.
- With `SaveOnConfigSet = true`, every effective assignment synchronously writes the entire configuration file on the calling thread.
- During batch declaration, temporarily disable `SaveOnConfigSet` and call `Save` once at the end.
- `Read` only replaces the file model; it does not rebind existing runtime entries. Use `Reload` to update existing bindings.
- `Reload` validates all bound entries before committing the new values as a complete set. Preparation failure leaves current runtime values unchanged.

### `ConfigEntry<T>`

```csharp
public T Value { get; set; }
public T DefaultValue { get; }
public string TableKey { get; }
public string Key { get; }
public Translator Name { get; }
public Translator Description { get; }
public Type ValueType { get; }
public ConfigFileEntry Entry { get; }

public event EventHandler<T> OnValueChanged;
public event EventHandler OnValueChangedBase;
```

The file model and events are updated only when old and new values are not equivalent. The typed event runs before the non-generic event. Reentrant assignments from an event handler are queued until the current notification pass finishes, while still running synchronously on the same calling thread.

### `ConfigEntry<T1, T2>`

```csharp
public EntryValue<T1, T2> Value { get; set; }
public T1 Value1 { get; set; }
public T2 Value2 { get; set; }
public event EventHandler OnValueChangedBase;
```

A dual entry is persisted as one complete value. Assigning `Value1` or `Value2` creates a new complete value and reuses the same codec, event, and automatic-save flow.

```csharp
ConfigEntry<int, int> size = config.Bind(
    "Window",
    "Size",
    800,
    600,
    new Translator("窗口尺寸", "Window Size"),
    valueDescription1: new Translator("宽度", "Width"),
    valueDescription2: new Translator("高度", "Height"));

size.Value1 = 1024;
size.Value2 = 768;
```

### Supported configuration values

| Category | Supported values | Example text |
| --- | --- | --- |
| Primitive | `sbyte`, `short`, `int`, `long`, `byte`, `ushort`, `uint`, `ulong`, `float`, `double`, `bool`, `string` | `42`, `1.5`, `true`, `"text"` |
| Enum | Any enum type; parsing is case-insensitive | `Warning` |
| Collection | Arrays, assignable `List<T>` types, or generic collections with a compatible constructor or public `Add` method | `[1,2,3]` |
| Tuple | A `ValueTuple` with at most 7 direct elements | `(10,"name")` |
| Dual entry | `EntryValue<T1,T2>`, normally created by the two-generic-parameter `Bind` overload | `10,20` |
| Custom value | Implements `IConfigEntryValue` and has an accessible parameterless constructor | Defined by the implementation |

The configuration format does not support `null`. Collection and tuple elements must also be recursively encodable. Strings use double quotes and support `\\`, `\"`, `\n`, `\r`, and `\t` escapes.

Collection entries are presented by the collection editor in the configuration GUI: when an ordered collection such as a one-dimensional array, `List<T>`, or `IList<T>` has elements of primitive types, enums, or tuples that are editable as a whole (such as `List<(int, string)>`), a summary button expands into per-element editing (reusing the value control of the element type, with remove and append support; tuple elements are drawn side by side in each row by the tuple editor). Unordered collections (such as `HashSet<T>`) and nested collections can still be read from and written to file, but they are displayed as unsupported types in the GUI.

Tuple entries are presented by the tuple editor in the configuration GUI: when a `ValueTuple` has 1 to 7 elements that are all primitive types or enums with no nesting, the element controls are edited horizontally in the same row (reusing the value control of each element type, consistent with dual-element entries). Element controls are measured per column across all rows in the same list and given fixed widths, so the same column is equally wide and aligned across tuple rows; boolean columns are measured by the toggle display word, enum columns by the longest description among all visible values, and the remaining columns by the text field style. Combinations whose elements are collections or nested tuples can still be read from and written to file, but they are displayed as unsupported types in the GUI.

### Custom configuration values

```csharp
public interface IConfigEntryValue : IEntryValue
{
    ConfigFileResult<string> Encode();
    ConfigFileResult<object> Decode(string content);
    ConfigFileResult<string> EncodeValueType();
}

public interface IEntryValue
{
    bool Equals(IEntryValue other);
}
```

The implementation type must have an accessible parameterless constructor because the framework creates a temporary decoder with `Activator.CreateInstance`. `Equals` should implement content equality so equivalent assignments and reload events can be skipped.

### File models and result types

These types support configuration-format extensions and direct file-model operations:

| Type | Purpose |
| --- | --- |
| `ConfigFileModel` | Static codec entry points for values, collections, tuples, and custom values |
| `ConfigFileSheet` | Ordered collection of configuration file tables |

## Configuration GUI metadata

### `EntrySliderAttribute`

```csharp
[EntrySlider(float min, float max, float step = -1f)]
public static ConfigEntry<float> Volume { get; private set; }
```

This attribute changes only GUI control selection and drag behavior. It does not constrain values from the configuration file or text input. A `step` less than or equal to zero disables snapping.

A dual entry can use composite metadata:

```csharp
[EntryGui(2)]
[EntrySlider(0, 320f, 3840f, 1f)]
[EntrySlider(1, 240f, 2160f, 1f)]
public static ConfigEntry<int, int> Resolution { get; private set; }
```

`EntryGuiAttribute.Count` specifies the number of slots. An indexed `EntrySliderAttribute` selects the slot for each element.

The configuration GUI uses `UserService.ConfigManagerType` and the current values of static properties to locate entries; it does not match by property name. A metadata-bearing property may be public or non-public, but it must be static, non-indexed, and initialized.

`UiMetadataHelper.GetMetadata(Type, IConfigEntry)` builds these runtime metadata objects from attributes on configuration-manager properties.

## Logging

### `LogDatabase`

```csharp
public const int MaxLogCount = 500;

public LogDatabase(UnityProvider unityService);

public IReadOnlyList<LogEntry> Logs { get; }
public int Seq { get; }

public event Action<LogEntry> OnLogAdded;
public event Action<LogEntry> OnLogRemoved;
public event Action<LogEntry> OnLogRepeated;

public void AddLog(LogEntry log);
public void AddLog(
    LogLevel logLevel,
    string msg,
    Exception ex,
    string member,
    string file,
    int line);

public void Debug(string msg, string member, string file, int line);
public void Info(string msg, string member, string file, int line);
public void Notice(string msg, string member, string file, int line);
public void Warn(string msg, string member, string file, int line);
public void Error(string msg, Exception ex, string member, string file, int line);

public void SubscribeWithSnapshot(
    Action<IReadOnlyList<LogEntry>> initialize,
    Action<LogEntry> onLogAdded,
    Action<LogEntry> onLogRemoved,

public void Unsubscribe(
    Action<LogEntry> onLogAdded,
    Action<LogEntry> onLogRemoved,
    Action<LogEntry> onLogRepeated);

```

The database retains at most 500 non-duplicate entries. Logs with equal thread, scene, level, message, call site, and exception text are merged into the first matching entry and update its repeat count.

Use `SubscribeWithSnapshot` when an initial snapshot and later changes must connect without gaps. Do not compose `Logs` and event subscriptions yourself for that use case.

### `LogWriter`

```csharp
public LogWriter(string directory, string fileName, LogLevel level);

public bool Enable { get; set; }
public LogLevel Level { get; set; }

public void Log(LogEntry log);
public void Write(LogEntry log);
public void Flush(bool forced = false);
public void Dispose();
```

File names use `<base-name>-yyyy-MM-dd-HH.log`. A writer does not switch files when the hour changes during its lifetime. `UserService.RegisterLog` automatically connects the database snapshot and later add/repeat events to a writer, so most callers do not need to instantiate `LogWriter` directly.

### `LogEntry` and `LogLevel`

`LogEntry` stores the sequence ID, time, thread, Unity frame, scene, level, message, call site, exception, and repeat state. `ToString` returns a multiline representation suitable for file output.

Log levels, from lowest to highest, are:

```text
Debug < Info < Notice < Warning < Error
```

## Live controls

The live-control service manages in-memory entries and does not read or write configuration files. A GUI write updates the entry cache and dispatches an event; business code should apply the new value to its target from that event.

### `ControlService`

```csharp
public ControlSheet Sheet { get; }
public event Action OnStructureChanged;

public void CreateTable(
    string key,
    Translator name,
    Translator description = null);

public ControlEntry<T> Bind<T>(
    string tableKey,
    string key,
    Func<T> valueGetter,
    ControlUpdatePolicy updatePolicy,
    Translator name,
    Translator description = null,
    IUiMetadata metadata = null);

public void Update(
    float unscaledDeltaTime,
    bool isVisible,
    bool becameVisible = false);

public void Dispose();
```

`Bind` immediately invokes `valueGetter` to obtain the initial cached value. Every successfully added table or entry synchronously dispatches `OnStructureChanged`.

The built-in `HControlGUI.GuiHost` drives the current user's control service each frame. A standalone `ControlService` requires its host to call `Update` explicitly.

### `ControlEntry<T>`

```csharp
public T Value { get; }
public Func<T> ValueGetter { get; }
public ControlUpdatePolicy UpdatePolicy { get; }
public IUiMetadata Metadata { get; }
public event EventHandler<T> OnValueChanged;
```

Automatic getter refreshes do not dispatch `OnValueChanged`; only a different value submitted by the GUI does. A control entry supports a single value and rejects multi-element types such as `EntryValue<T1,T2>`.

### `ControlUpdatePolicy`

```csharp
public static ControlUpdatePolicy EveryFrame { get; }
public static ControlUpdatePolicy EverySecond { get; }
public static ControlUpdatePolicy WhenVisibleEveryFrame { get; }
public static ControlUpdatePolicy WhenVisibleEverySecond { get; }
public static ControlUpdatePolicy Never { get; }
```

Per-second policies use unscaled time. `WhenVisibleEverySecond` refreshes immediately on the first frame after the window becomes visible and restarts its timer.

## Hotkeys

### `Hotkey`


`Hotkey` implements `IConfigEntryValue` and can be used directly as a configuration type. Commas separate alternative chords, while plus signs join buttons in one chord:

Setting `GlobalValid = false` disables every hotkey. Setting an instance's `Valid = false` disables only that instance.

## Translation

### `Translator`

```csharp
public Translator(string chinese = "", string english = "");

public static LanguageType DefaultLanguage { get; set; }
public static event EventHandler<LanguageType> OnDefaultLanguageChanged;

public LanguageType LanguageType { get; set; }
public string Chinese { get; set; }
public string English { get; set; }
public string Default { get; }
```

Instances default to `LanguageType.Default`, which follows the global `DefaultLanguage`. `ToString` and the implicit conversion to `string` both return the text selected by the current language.

```csharp
Translator title = new Translator("设置", "Settings");
Translator.DefaultLanguage = LanguageType.Chinese;

string text = title; // "设置"
```

`LanguageType.None`, unknown values, and a global language that remains `Default` resolve to English. `Translator` does not load resources and does not fall back to the other language when the selected text is empty.

## GUI

### Built-in windows

| Host | Default hotkey | Data source |
| --- | --- | --- |
| `HConfigGUI.GuiHost` | `F1` | User `ConfigService` |

## Unity providers

### `IUnityProvider`

Abstracts time, frame, scene, keyboard, gamepad, mouse, clipboard, math operations, and the quit event. The default singleton implementation is `UnityProvider.Instance`.

### `IUnityGuiProvider`

Abstracts Unity IMGUI windows, layout, labels, buttons, text fields, sliders, and style access. The default singleton implementation is `UnityGuiProvider.Instance`.

Shared GUI editors receive these dependencies through interfaces so tests can replace them with mocks. Low-level hotkey types currently hold a concrete `UnityProvider`, not `IUnityProvider`.
